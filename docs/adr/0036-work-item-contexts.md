# 使用工作项隔离多需求上下文

## 决策

项目只维护一份 `AGENTS.md` 和 `.agent-workflow/`。需求、任务和缺陷作为 `30-records/work-items/<ID>/` 下的独立工作项，保存各自的当前状态、需求变更、分阶段进展及按事实创建的局部记录。

## 背景

原有结构只有一份根 `current-status.md` 和公共日志，适合单条进行中的工作流。多个需求并行时会把一个任务的进展、验证和风险暴露给另一个任务，无法可靠恢复目标上下文。

## 影响

- 项目公共规则、架构、模块索引和跨任务记录仍只有一份，禁止复制到任务目录。
- 新项目默认创建空的 `work-items/` 入口；旧工作流保持可用，升级时不自动拆分历史。
- Git 和 worktree 不属于第一期依赖；它们后续只作为可选代码状态适配能力。
