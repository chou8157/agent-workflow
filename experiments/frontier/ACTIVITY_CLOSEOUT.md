# 单节点活动收口实验

`activity_closeout.py` 是实验副本中的最小写入器，用于验证单节点自治和活动事实唯一性。

## 行为

- 只更新目标工作项自己的 `.state.json`，同目录保留一个 `.state.json.lock` 协作锁文件，不读取或更新父节点、关系库和其他节点。
- 写入前校验证据文件路径、行号和 SHA-256；证据正文仍是补充说明，活动摘要只保存在 `activity_records`。
- 同一 `id` 与完全相同的内容重复提交返回 `unchanged`，不会再次写文件。
- 同一 `id` 但内容不同会拒绝，避免覆盖历史事实。
- 活动追加、工作项状态更新、创建和旧状态迁移使用同一工作项锁，锁覆盖读取到替换全过程；超时明确报错。进程退出后操作系统释放锁，不需要手动删锁文件（删除可能破坏并发互斥）。
- 写入使用唯一临时文件、文件刷盘、原子替换和目录刷盘。替换前失败保留原状态；替换后刷盘失败明确返回“结果待确认”，用相同活动 ID 重试检查，不声称一定未写入。
- 进程被强制终止可能留下 `.tmp` 文件；它们不作为权威事实，也不进入聚合。恢复只读取 `.state.json`，不会自动导入残留临时数据。
- 新入口使用引用行范围哈希；正常追加日志不会让旧活动失效，修改引用行仍会出现缺口。已有整文件哈希引用维持原行为。

## 试验边界

入口和使用方法见 `LIGHT_USAGE.md`。当前锁实现适用于本机 macOS/Linux 文件系统，不宣称跨机器或共享网络文件系统一致性。只有实验版写入入口协作持锁；不能混用旧安装版写入器或绕过入口手工覆盖 `.state.json` 后仍要求并发保证。

该写入器不代表稳定版已经支持活动收口，也不会自动把 `progress/` 或 `validation-log.md` 转成活动记录。故障注入和进程强制终止不能替代真实断电验证；真实项目写入和稳定版集成尚未开展。
