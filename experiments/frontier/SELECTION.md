# 多节点工作流验证结论与选型

版本：2026-10-11。范围：仅实验 worktree，不代表稳定版已上线。

## 结论

1. **单节点自治保持为硬边界。** 本地原 CLI 在关系配置关闭、损坏、断开、退出和服务不可用时仍能创建、更新、读取自身工作项；聚合只写独立派生运行目录，不写节点工作流文件。文件、SQLite、F-log、PostgreSQL、Neo4j 均经过同一套 P4 生命周期测试。P4 本地 135 项通过；五后端同口径自治测试 5 项通过；有界 CLI 121 次观测全部受响应上限约束。
2. **当前不选出可直接上线的 Agent 编排策略。** P3 真实 fresh 子会话共 138 次（72 final、66 worker），独立人工 oracle 验收只有 C 14/24、H 15/24、M 11/24 final 重复通过，合计 40/72（55.6%）。失败集中在缩小 registry 覆盖、错误 skipped 类型、来源哈希/冲突处理和越界工具；不能用提示词解释替代失败，也不能把确定性模拟结果当作真实 Agent 能力。H 的通过率最高但仍未过硬门槛；M 还有约 13,097 秒异常单次耗时，因此没有生产赢家。
3. **默认关系权威选择 SQLite。** 对个人单机、多进程、关系修改和局部查询，它比全文件快照更适合持续更新，具有事务、索引和标准备份接口，且不引入常驻服务。节点工作事实仍由各节点原工作流文件保存，SQLite 只保存身份、定位、关系、授权版本和运行控制记录。
4. **PostgreSQL 保留为团队/多机部署候选，暂不作为个人默认。** 真服务 16.15 的 320/320 矩阵、280/280 原生后代查询、44 项契约及容器强杀恢复均通过。它解决共享关系权威和多客户端并发，但带来服务、账户、备份、网络和迁移运维。Neo4j Community 5.26.31 同样通过关系契约，却需要较大常驻资源；当前一致快照实现还需要元节点写事务，和只读权限目标存在冲突，因此不作为首选关系库。
5. **F-log 不作为默认后端。** 它能减少单次写入载荷并通过提交水位恢复，但需要初始快照、链日志和水位三份权威，读取重放、尾部隔离、压缩轮换和备份维护都更复杂。除非 SQLite 的实际写入或部署约束成为瓶颈，否则不承担这部分复杂度。

## 保留的产品模型

### 权威和数据流

- 节点工作项、过程记录、验证文档是所属节点的唯一事实来源；父节点只保存引用、版本和派生汇总。
- 关系库是身份、定位、`contains`/`related` 边、授权和关系版本的唯一控制面权威；它不是可随时删除的缓存，也不保存工作事实副本。
- 汇总运行记录保存请求模板、范围、来源哈希、覆盖、缺口、冲突和观察时间。报告文本是派生物，不能回写节点事实。
- 普通本地工作不触发外部同步。跨节点读取由用户或上级 Agent 明确发起；跨节点写入不在第一版范围。

### 查询和上下文

- 模型入口使用 `self/subtree`、节点数、深度、总耗时和响应字节预算；超限必须显式 `partial`、`failed` 或 `skipped`。
- 首屏只返回 manifest、计数、版本和结果 handle；通过 `page` 分页事实/来源/缺口，通过 `evidence` 按 SHA-256 与行号下钻。
- 完整 N 节点汇总的总工作量仍随 N 增长。预算限制单次上下文和总执行，不承诺无限节点恒定成本。
- “完整”只表示本次已登记、已授权且可核验的范围完成；不存在日期的状态保留 `unknown`，不能用更新时间或文件时间补造业务活动。

### 关系修改和恢复

- 所有关系写入经过版本比较、引用校验、重复边检查和 `contains` 无环校验；不同时编辑 YAML/JSON 和数据库。
- 迁址改变 locator，不改变逻辑身份；备份副本默认不能执行本地任务或加入网络；加入、退出、恢复和迁址都保留可对账状态。
- 关系备份、节点资料备份和运行记录备份分别管理。数据库逻辑导出用于迁移核验，不能替代服务原生灾备。
- 单库事务不等于跨节点源文件同一瞬间快照。来源读取前后校验发现变化时，运行降级为 stale/partial。

## 正式开发路线

1. **D1：SQLite + 本地有界查询。** 将实验接口重写为稳定模块，默认不启用网络；保留原本地 CLI 路径和输出语义。加入 schema 版本、迁移、备份恢复、节点身份初始化和关系变更审计。
2. **D2：确定性聚合控制面。** 先由程序固定授权集合、时间窗、预算和来源版本，再让模型处理有界结构化输入。程序验收覆盖、身份、哈希、重复和冲突；模型失败返回缺口，不自动重试成“成功”。
3. **D3：小规模真实 Agent 适配。** 先以 C 作为受控基线（单次 final、最少调用），对 1–3 个真实项目和代表性周报模板做盲测；H 只有在 worker 传递的 registry、覆盖和来源校验达到预设门槛后再开放。M 暂缓，除非重新证明分批能稳定降低上下文和总延迟。
4. **D4：团队服务扩展。** 只有出现跨机器并发和集中权限需求时接入 PostgreSQL；以同一接口运行迁移、备份、网络分区和权限撤回演练。Neo4j 需要先解决只读快照权限和资源基线，再决定是否保留。
5. **D5：灰度与退出。** 实验节点与稳定版并行，提供导出、停止关系服务仍可本地工作、删除关系注册不删除节点文件的退出路径。达到事先确认的准确率、缺口可见性、恢复和资源目标后，另行提交合并评审；失败则只删除实验注册和控制面，保留节点资料。

## 重新评估条件

- SQLite 关系写入冲突、查询或备份耗时在真实工作负载下超过目标；
- 真实用户要求跨机器共享、集中权限、审计或高并发；
- 模型在固定模板盲测中持续出现 registry 缩小、来源哈希错误、冲突静默消解或工具越权；
- 节点规模、关系密度、事实文档大小超出本次已验证的 1000 节点和 100 KiB 级合成边界；
- 工作流结构或稳定版入口发生变化，导致 P4 来源覆盖不再成立。

达到上述任一条件时，重新冻结数据和权重，复跑统一契约；不通过增加 YAML 字段或后台同步来掩盖一致性缺口。
