# 前沿工作流实验：独立验收与选型评审

- 工作项：`W-20261009-frontier-workflow`；评审日期：2026-10-10。
- 状态：第 1–9 节为实施前实验设计及 PLAN v1 二轮评审，当时尚未运行候选实现；其中数量和阈值为建议协议。最新协调器实施验收见第 10 节。
- 依据：本轮明确需求、项目 `AGENTS.md`、目标工作项入口及质量门禁；旧状态中的“准备阶段”不代表本轮未获实验授权。
- 范围：独立设计、测试与审查结论有效性；不选择存储、不改实现、不操作 Git 或安装版。

## 1. 先冻结语义，再比较实现

1. 节点既可独立管理自己的任务，也可聚合下级；脱离父节点后，本地已有任务仍可读写，原有身份不变。
2. 独立能力指不依赖父节点/上级服务；是否需要自己的数据库服务单独列出，不用“零服务”预先淘汰候选。
3. 父级按需发起统一读任务；横向访问必须携带明确范围；空闲时不常态复制、轮询或传播子节点任务数据。
4. 事实身份为 `(authority_node_id, task_id)`；同名任务可并存，同一事实多条可达路径只计一次。
5. 权威事实只在所属节点写入；缓存、索引、摘要均标识来源和版本，不成为可独立修改的第二份权威事实。
6. 完整性相对固定的请求范围、关系版本和预期来源清单判断；清单不可得时只能返回未知完整性。
7. 聚合状态至少区分 `complete / incomplete / failed`；来源级缺失、拒绝、超时、损坏、版本变化均可追溯。
8. 关系形成环时可拒绝变更或显式报告环；预先冻结策略。静默裁边、无限递归均失败。
9. 当前事实、指定历史版本和允许陈旧缓存是三种不同请求；候选不能通过放宽新鲜度换取成功率。
10. 保留每个候选的部署、事务和故障假设；无法实现某一必需语义时记录失败，不能临时改需求。

## 2. 不可抵消的硬门槛

| 门槛 | 操作与必验条件 | 失败判定 |
| --- | --- | --- |
| H1 独立节点 | 分别把叶子/中间/根当独立节点，断开父级后创建、更新、重启恢复自身任务 | 依赖父级在线、丢任务或重建身份 |
| H2 权威与来源 | 更新唯一权威任务；核对所有返回事实的身份、版本、内容哈希、证据定位 | 分叉权威、旧事实冒充最新或证据无法回读 |
| H3 范围与隐私 | 父读后代、显式横向授权、无授权横向读；放置范围外诱饵任务 | 任何内容、标题或范围外敏感计数泄漏 |
| H4 完整与去重 | 本地任务与多层后代并集，菱形多父、相同本地 ID、空节点并存 | 多计、少计，或缺失来源仍标记 complete |
| H5 按需委派 | 比较查询前后源数据哈希；空闲观测至少两个配置调度周期 | 读任务写源事实、隐藏常态同步或配置周期无法审计 |
| H6 关系与并发 | 查询期间新增/撤销父子关系、撤销横向授权、并发更新同任务 | 越权返回，或混合版本结果冒充一致快照 |
| H7 故障恢复 | 超时、拒绝、坏文件、失效连接、查询中进程中断后重试 | 静默漏项、重复生效、挂死或恢复后数据损坏 |
| H8 审计与预算 | 每次请求保存范围、版本、来源结果、缺口、成本、结论证据 | 不可复现、超限静默截断或只给成功摘要 |

所有适用硬门槛须通过后才能进入成本排名；不支持、未测、失败分别记录，不能合并成“跳过”。
数据与范围错误容忍度为零；性能、上下文预算是独立约束，不能补偿正确性失败。
并发撤权以服务端定义的授权判定线性化点为准；若产品要求响应前再次核权，所有候选统一执行。
跨节点无法提供原子快照时，返回读取版本向量及变更/不确定标记；不能宣称全局瞬时一致。

## 3. 可机械验证的独立 oracle

- 输入由测试器保存：不可变事实集 `F`、带版本关系集 `E`、权限集 `P`、操作序列 `J`、请求 `Q`、故障计划 `X`。
- 小规模使用手工列明的预期 ID 集；随机规模由独立参考模型计算，禁止调用候选的遍历、过滤、序列化或计数函数。
- `ExpectedSources(Q)` 由冻结关系与权限计算；每个预期来源恰有一个终态：成功、明确为空或结构化缺口。
- `ExpectedFacts(Q)` 是合法来源中满足条件的权威事实身份集合；允许缺口时仅与已成功读取部分比较，不伪造缺口内数量。
- 按 `Q` 指定的版本/新鲜度取事实；核对规范化字段和 SHA-256，而非只比较总数或自然语言相似度。
- 输出事实身份集与预期集相等；计数按该集合计算，禁止对子摘要计数再次求和。
- `complete` 当且仅当范围清单已验证、所有预期来源成功、版本策略满足且没有裁剪；零条结果不自动等于 complete。
- 每条证据回读须匹配 `(authority, id, revision, hash)`；源被删除时须有可核验历史证据或明确“证据已不可得”。
- 关联路径与事实身份分离：一个事实可列多个父路径，但业务计数一次；路径数量另列，禁止无限展开路径。
- `J` 写入请求附幂等键与预期版本；验证操作重试只生效一次，并发冲突显式拒绝或按已冻结规则合并。
- 故障计划确定到“来源/操作/阶段”；测试器核对实际触发日志，未触发注入不算故障用例通过。
- 每次结果保存候选版本、配置、输入哈希、随机种子、原始输出、核验差异、退出码与时间，不依赖人工转述。

## 4. 验收矩阵与变形测试

| 编号 | 固定输入/变化 | 必须保持或改变的结果 |
| --- | --- | --- |
| M01 | 单节点 3 个自身任务，再把同节点接入父级 | 自身读写及身份不变；父级聚合新增这 3 个身份 |
| M02 | 深度 1/3/8，各层都有自身任务 | 根聚合等于所有可达事实并集，中间节点自身任务不能遗漏 |
| M03 | 菱形 A→B/C→D，再增加第 3 条通往 D 的路径 | D 事实只计一次；来源路径变化，不改变事实数量 |
| M04 | 两节点各有 task_id=1，再把其中一个标题改成相同文本 | 两个事实仍分别计入；禁止按标题/本地 ID 去重 |
| M05 | 重排文件、目录、行、插入顺序和关系顺序 | 规范化事实集、计数、缺口集合不变 |
| M06 | 增加 100 个范围外节点与唯一诱饵字符串 | 当前结果不变；输出、日志可见上下文与 Agent 工具读取均无诱饵 |
| M07 | 同一有效请求与写入重试 3 次 | 读取语义一致；写入仅一次生效，审计能辨认重试 |
| M08 | 来源 D 从正常→超时→恢复，另有真实空来源 | 超时产生 D 缺口；空来源保持成功为空；恢复后恢复原完整集合 |
| M09 | 新增、删除、迁移父关系；查询中更改关系 | 按冻结版本返回，或明确版本变化；撤销后新查询不含旧分支 |
| M10 | 创建关系环、悬空引用、同权威同版本不同内容 | 按预定策略拒绝或报错；禁止静默挑一个内容继续 |
| M11 | 同时更新状态与读取、撤权与读取、删除与读取 | 符合已声明事务/授权时点；未知与冲突不能归类为已完成 |
| M12 | 缩小输出预算、缩短超时、分页重复/漏页 | 结果显式 incomplete 且列明缺口/游标；禁止把截断当完整 |
| M13 | 节点迁址、索引删除重建、缓存过期/污染 | 权威身份不变；重建前后事实集一致，缓存污染不能改变权威 |
| M14 | 服务/进程在读前、读中、提交前后中断重启 | 已确认写入符合持久化承诺，未知提交可查明，恢复读结果可追溯 |

随机测试固定公开种子 0–29，每种至少 100 次操作；另保留 10 个隐藏种子用于最终复验。
规模分开测：节点/任务为 1/10、100/1,000、1,000/100,000；链、宽树、多父 DAG 三种形态独立报告。
深度、扇出、任务正文长度、共享后代比例分别变化；不要只扩大任务数量而宣称覆盖复杂关系。

## 5. 真实 Agent 与模拟器的证据边界

- 模拟器证明协议、存储、故障响应及集合正确性；不证明 Agent 能找到入口、选对范围、读懂缺口或正确回答。
- 真实 Agent 固定模型版本、推理档、工具权限、任务模板、起始上下文和预算；每次独立会话，不能继承上次答案。
- 统一读任务至少含请求 ID、目标节点、范围/权限、过滤条件、版本要求、预算、截止时间与结构化返回约定。
- 真实测试 8 场景：独立读写、多层汇总、菱形去重、横向授权、不可达来源、陈旧摘要、关系变更、预算不足。
- 每候选每场景先 1 次烟测；通过确定性门槛者再各 3 次独立运行，顺序随机，最多 4×8×3=96 次正式运行。
- 结构化事实由 oracle 评分；正文逐项核对事实、缺口披露和证据引用，严重性标准预先冻结，歧义由独立复核者裁定。
- Agent 错读范围、捏造 complete、被任务正文中的越权指令诱导，均单列失败；不能让模拟器代答计为 Agent 成功。
- 小样本零失败只证明这些运行通过；报告分母、置信区间及失败轨迹，不外推“生产可靠”。

## 6. 公平次序、成本和选择规则

1. 候选登记文件、SQLite、PostgreSQL、图数据库的实际产品/版本、架构、部署假设；未运行的数据库不得由替身代表。
2. 先冻结上述公共语义、数据与评分规则，再实现最小端到端路径；开发预算相同，额外调优时间单列。
3. 先比较共同 API 下的存储/查询正确性，再比较各自原生 Agent 使用流程；不能混用两轮得出单一性能结论。
4. 依次执行小样本 oracle、变形/故障、并发、规模、真实 Agent；确定性硬门槛失败者修复后全候选复跑受影响用例。
5. 4 个候选按随机映射后的拉丁方 ABCD/BCDA/CDAB/DABC 轮换；性能互斥运行，使用同一机器、数据与并发级别。
6. 每场景冷启动 10 次、预热后 30 次；分别记初始化/导入/建索引、首读、热读、写入、恢复，不隐藏准备成本。
7. “冷”明确是新进程/新数据库/清空缓存中的哪一种；未清操作系统缓存不得标为物理冷读。超时与失败不能从分母剔除。
8. 延迟报告中位数、p95、最大值与原始样本；30 次的 p95 仅作探索性指标，不伪装稳定尾延迟保证。
9. 工程成本记录实际开发/配置/调试时间、依赖、常驻内存、存储/索引大小、备份恢复与迁移步骤；区分一次性和每次成本。
10. Agent 成本记录真实输入/输出/缓存 token、各层委派工具结果、重试数、会话数及总墙钟时间；父会话与所有子会话都计入。
11. 没有 token 计量时可报告字符/字节代理，但不得命名为实测 token；模拟器输出长度不能推导 Agent 总上下文成本。
12. 只对全部硬门槛通过的候选画成本/延迟/上下文 Pareto 比较；没有预先业务权重时不设综合分强推赢家。
13. 所有候选均失败则结论为“当前无通过方案”；只有一个实现完成则结论为“该原型证据”，不能宣称技术选型胜出。

## 7. 会制造虚假可靠结论的做法

- 让实现生成自己的期望值、只核对总数、把不同内容但数量相同视为成功；都会隐藏身份、版本或漏项错误。
- 文件全量扫描与数据库预计算索引比较却不计更新成本；或把 SQLite 内存模式代表持久化 PostgreSQL/图数据库。
- 只测单父树、无自身任务的聚合节点、全来源可达、低并发；这些避开了本需求最关键的失败路径。
- 摘要声称完整但不附预期来源清单；局部成功被当总体成功，超时来源的零值被当真实零值。
- 用重试后的最好成绩、删掉失败样本、调整新鲜度/权限/预算帮助单一候选、只报告热缓存平均值。
- 把数据库事务保证直接当跨节点事务保证，把静态扫描或模拟器通过直接当真实 Agent/生产验收。
- 在看过结果后更改权重或通过阈值；发现新要求可以修订协议，但旧结果作废并对所有候选同口径重跑。

## 8. PLAN v1 二轮评审：实现前必须冻结的规则

评审对象：`PLAN.md` v1，SHA-256 `a996eb53b35fbdb50444ed3278b351a2d0cc7b8bbc28ec88d0e36ec7d5f760f7`；结论为“P1 可作为筛查层，以下契约补齐后开始实现”。
主 Agent 已限定 P1 为 F/S 实际持久化与 C/H 确定性执行；P/G 环境缺失保持 `not_run/environment`，本轮不形成技术赢家。

| 项目 | 当前缺口与影响 | 实现前可操作修正及最小验收例 |
| --- | --- | --- |
| R1 完整性真值 | A4/A8 未定义 full/partial 与 complete/incomplete 的准确对应，缺失的分母可能被实现自行缩小 | 统一返回枚举及映射；`full` 仅当范围已知、预期来源全部终结成功、分页耗尽、无冲突/截断且满足版本要求。坏成员清单返回 failed 或 partial + scope_unknown，不能把已响应来源当分母。 |
| R2 来源与事实覆盖 | 节点成功不代表其全部任务读完，损坏单条记录可能被过滤掉 | 返回预期来源、逐来源状态、未覆盖来源/分页/记录缺口；已知应读节点被拒绝算缺口，按请求预先排除的范围外节点不算缺口。一个节点 10 条中坏 1 条须 partial，不得 full=9。 |
| R3 身份与版本 | A5 将“同身份不同值”一概判冲突，会误伤正常新版本；同需求的贡献与共享事实仍缺判定键 | `fact_id=(authority_node_id, local_id)`；revision/hash 不入身份。同需求在 A/B 的贡献各计一次，共享事实引用 D 只计 D 一次。同视图同版本不同内容为冲突；不同版本按冻结版本策略选取或报读取期间变更。 |
| R4 视图绑定 | 第 6 节仅说分支/worktree 不默认合并，未定义默认视图与查询快照 | 请求固定 node→view 映射，view 绑定内容版本/快照；分支名本身不是不可变版本。同 fact 在 main/实验分支不得默认相加；缺少映射须报歧义，跨视图比较单列差异且不产统一业务总数。 |
| R5 权威归属 | 候选表只说明关系权威，没有解释任务文档、提取事实、关系目录与快照谁可写 | 分开登记关系权威、任务权威、视图定位、提取/缓存产物。P1 若只测关系持久化，任务原文件为唯一事实源；控制目录的副本标为派生。删除派生索引后可重建，删除关系权威必须恢复备份或失败。 |
| R6 缓存契约 | PLAN 尚未定义缓存键、新鲜度与撤权行为，缓存会掩盖源失败或跨视图泄漏 | P1 明确禁用内容/授权缓存并记录；启用时键覆盖范围、视图、查询条件/时区、关系/权限版本、来源版本及协议版本，并在命中时复核访问权。源失效时旧缓存不能被称为实时 full；只能按显式历史/陈旧策略返回。 |
| R7 权限与路径 | 父可读下级不等于自动继承全部横向权限，图可达与授权可能被混用 | 定义 relation_scope 与 read_grant 各自判定，默认范围外不读；委派令牌只能缩小范围。菱形一条路径获准、一条拒绝时按既定授权语义判读，不得靠扩大子任务权限“解决”缺口。 |
| R8 调度与归并 | H 可能退化为中央直接扫描后分组，或把子级 full 当根级 full | 记录实际委派边、子请求范围、来源覆盖与预算；根级核验自己的预期来源集合。注入下级漏来源、重复响应、错误 full，根必须检出；若当前接口无法检出则明确该信任边界。 |
| R9 独立 oracle | “独立生成预期值”未说明读取器是否共享，容易所有候选一致错误 | 小样本手写身份/字段/缺口集；期望不调用公共事实读取器、候选遍历或归并。F/S 可以共享被测读取器，但读取器自身需由独立预期检验；新增 1 个隐藏多父样本复验。 |
| R10 自治边界 | A1 可能仅验证源文件存在；实际单节点入口仍偷偷依赖损坏的关系库 | P1 做自身任务最小读写/重开路径，并断开父关系或损坏可选关系索引后复验；若未接入真实工作流，只记“原型自治通过”，A1 产品集成仍待验。 |

R1–R10 可以在临时 contract 中冻结，不要求扩成长期插件接口。P1 未实现的能力必须标出约束和待验，不能由“未来可扩展”解除硬门槛。
当前 partial 允许返回可信子集；零事实但已知缺口仍为 partial，查询/范围无法建立且没有可信结果则 failed；空且覆盖完成才是 full。
未知任务数量保留 unknown；不得填写 0，不以覆盖了已知节点百分比代表覆盖全部任务。不可枚举的后代应保留未展开边界。
