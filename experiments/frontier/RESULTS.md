## 2. 验证结果

- 最终测试：`179 passed in 9.20s`，其中原稳定版 29 项、实验 150 项，零跳过；证据 `evidence/tests-final-v3.xml`。
- 105 项协调器测试在 Python 3.8/3.10 各完整通过；覆盖多层自身事实、多父去重、范围/时间、冲突、缺失、预算、分页和来源路径边界。
- 独立 oracle：400 个随机 12 节点 DAG，C/H 共 800 次核查；1200 节点深链通过。这两组注入事实读取器核验拓扑；另有 14 项真实来源文件边界通过。见 `evidence/independent-probe-v2.json`。
- 文件存储 23 项、SQLite 13 项含真实四进程竞争、CAS、并发读和提交故障；这不等于强杀、断电或跨机器恢复验证。
- 自治隔离 5 项：4 项为 F/S × 关闭/损坏时原始单节点 CLI 继续处理本地任务，外部节点与控制目录哈希不变；1 项为全新进程导入不创建关系权威库。这是尚未接入产品时的隔离证明，集成后必须重测。
- 稳定版隔离：73 个稳定文件与基线 `31989c7` 一致；主工作区 `main` 干净。当前安装版 66 文件与稳定源码一致；没有安装版历史哈希，不能宣称做过安装版前后对照。见 `evidence/isolation-final.json`。

每格 5 次，轮换候选次序；F/S × C/H 四格同输入、同返回语义，源码在每轮运行期间稳定。

| 数据规模 | 拓扑 | 运行次数 | 通过 |
| --- | --- | ---: | ---: |
| 1/10/100/1000 节点，每节点 1 条命中事实 | 平铺、均衡、深链、多父 DAG | 320 | 320 |
| 10/100 节点，每节点 10 条命中事实 | 平铺、深链、多父 DAG | 120 | 120 |
| 10/100 节点，每节点 100 条命中事实 | 平铺、深链 | 80 | 80 |

## 3. 对产品设计有用的发现

### 管理层级不应强制决定执行层级

1000 节点、每节点 1 条命中事实时：

| 拓扑 | C 累计转发引用 | H 累计转发引用 |
| --- | ---: | ---: |
| 平铺 | 999 | 999 |
| 均衡树 | 999 | 4547 |
| 深链 | 999 | 499500 |
| 多父 DAG | 999 | 997000 |

当前 H 每一级保留后代引用集合，深链累计工作量按 N×(N−1)/2 增长。
1200 深链为 719400 次引用转发；避免递归栈溢出不等于避免 CPU/内存放大。
这暴露的是当前 H 实现的成本，不是对所有分层 Agent 设计的否定；下一步应比较共享结果句柄、
分批读取与混合调度，而不是逐层复制全量事实或依赖逐层自然语言摘要。

### 存储和上下文是两类问题

正式矩阵的根 manifest 为 317–340 字节，最大事实页 4027 字节，均在 4096 字节分页预算内。
这证明程序可以返回计数和产物指针，不必在入口返回完整网络；没有测到真实模型 token，
也没有证明 Agent 多轮下钻后仍能维持上下文预算。完整覆盖表与事实仍保存在查询产物中。

节点/深度预算目前限制来源读取范围，关系快照与完整范围枚举仍可能为 O(N+E)。
H 的引用集合还可能进一步放大内存，因此本轮不能声称全查询 CPU/内存已严格有界。

### 数据库在本轮的优势只属于这个实现和口径

1000 节点的关系快照中位耗时：F 约 12.5–20.1 ms，S 约 5.1–8.1 ms；
一次定位修改中位耗时：F 约 44.4–69.0 ms，S 约 25.9–40.6 ms。
关系修改只改变指定节点记录，其他节点源文件不变；F 重写完整关系文件，S 采用差量 SQL，
但两者仍有全关系校验成本，后续需单独测原生索引/局部查询与分片文件变体。

示例：1000 节点深链，公共事实读取与归并 `query_ms` 的中位数为：

| 后端 | C | H |
| --- | ---: | ---: |
| F | 206.19 ms | 226.94 ms |
| S | 205.88 ms | 227.59 ms |

`query_ms` 不含关系快照加载、分页和结果落盘，不能当完整端到端时延；数据库加载成本在 `snapshot_ms`。
每格只有 5 次，未清操作系统缓存、未做独占机器测量；只报告探索性中位数/min/max，不排名微小差异，不宣称可靠 p95。
本轮没有公平比较服务后端、原生索引、运维成本或真实 Agent，因此没有存储赢家。

## 4. 失败证据与修复

独立评审实际复现并推动修复了：跨时间窗版本冲突被漏报、JSON 布尔值与数字被误判相等、
外来来源被重标、符号链接替换越界、Python 3.8 缺少 dir_fd、失败读取字节漏计、布尔版本绕过 CAS。
具体初始结果和最终哈希见 `implementation-review.md`；修复前 XML 保留，不能被最终通过记录覆盖。

首轮规模基准 320 个样本被来源路径检查判失败：临时目录的 `/var/...` 与规范 `/private/var/...`
指向同一文件，基准预期没有规范化。这是基准缺陷；没有把它计作 F/S 的产品失败。
修复后新增目录别名回归，对四格全部重跑，320/320 通过。旧证据 `p1-scale-20261010.json`
与旧完整输出仍保留，正式结果使用 `p1-scale-20261010-v2.json`。

## 5. 硬门槛剩余缺口与继续条件

| 门槛 | 已覆盖 | 仍需验证 |
| --- | --- | --- |
| A1 自治 | 未集成时本地 CLI 独立运行、关系损坏隔离 | 接入产品后加入/退出网络，根/中间/叶子真实读写恢复 |
| A2 只读与权威 | 源前后哈希、单来源身份、普通本地操作不改外部文件 | 真实 Agent 工具写边界与真实业务文档提取 |
| A3/A5 等价与去重 | 手写预期、400 随机 DAG、深链、同名/多版本冲突 | 真实多项目贡献统计口径、Agent 错误响应和摘要证据 |
| A4 完整性 | 固定关系快照、逐来源终态、明确 partial | 动态成员/权限变化与真实委派响应核验 |
| A6 持久一致性 | 四进程 CAS、写锁/事务、基础失败注入 | P/G 实例、16 写者、强杀重启、备份恢复和迁移 |
| A7 来源/时间/权限 | 时间边界、双读变化检测、路径替换拒绝 | 动态撤权、操作系统隔离、跨主机授权；双读不是全局快照 |
| A8 预算 | 节点/深度裁剪和字节分页、超限显式失败 | 时间/内存预算、取消重试、真实父子会话累计 token |

接续顺序按 PLAN：P2 服务后端与故障恢复 → P3 真实 Agent 的 C/H/M 同口径测量 → P4 真实记录副本、自治集成、迁移退出与选型复核。
P2 先建立专用隔离服务环境并记录版本/持久化配置；不能连接真实业务库来补测试。
P3 先固定模型、模板、工具权限和运行记录方式；P1 字节数据不能充当模型成本。
全部必要硬门槛有证据后再做成本取舍；证据不足允许继续保持未选型。
