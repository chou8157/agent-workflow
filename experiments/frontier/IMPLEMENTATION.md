# 正式开发方案

本文件定义多方案实验之后的产品实现边界。候选的实测结果、最终选择和限制以 `SELECTION.md` 为准；这里的开发阶段尚不代表稳定版已经具有这些能力。

## 1. 使用方式

每个项目继续使用自己的 `AGENTS.md`、`.agent-workflow/` 和既有任务命令。未加入网络、关系库损坏、父节点不可达、节点身份配置损坏，均不应阻止原有本地操作。网络功能是单独入口，不成为本地命令的前置条件。

一个节点既能有自己的工作，也能有下级。用户在任意节点可以选择：

- 只处理当前项目：沿用原工作流，仅写当前项目。
- 查看自己的关联：只返回有界目录，不递归加载项目文档。
- 汇总自身和授权下级：创建一次有明确范围、时间和预算的运行。
- 打开某条结论的来源：按节点、文档版本和行号读取限定片段。

示例问题“这周做了什么”首先确定时区和周区间，再区分完成事项、进行中的进展、验证结果和未覆盖部分。没有活动日期的事实保留日期未知；不能使用文件修改时间、采集时间或任务更新时间替代业务活动时间。

## 2. 三类数据与唯一权威

| 数据 | 唯一可写权威 | 其他位置可以保存什么 |
| --- | --- | --- |
| 项目任务状态、过程记录、验证依据 | 所属节点的原工作流文件 | 带源路径、版本/哈希、采集时间的引用和派生结果 |
| 节点身份、定位、成员关系、授权声明 | 当前网络的一份关系库 | 有版本的导出、只读目录页和恢复备份 |
| 一次汇总的请求、执行状态、覆盖表 | 发起方的运行记录 | 只读结果页、证据索引、用户导出的报告 |

关系库是需要备份的权威，不能当成可随时丢弃的索引。项目内部继续维护原有事实，不额外维护一份“对外状态”。报告中的自然语言是派生解释，不能反向覆盖来源。

查询缓存和搜索索引可以重建。缓存键至少覆盖请求范围、关系/授权版本、节点视图及来源哈希；有效期不是正确性的证明。来源发生变化或权限撤回时，旧结果只能作为明确标记的历史观察，不能继续声称当前完整。

## 3. 身份、关系和授权

节点使用稳定逻辑 ID，路径是可修改的定位。迁址更新一项定位，不要求重写所有祖先文件。分支与 worktree 具有显式视图身份，默认不将两份工作区的状态合并。复制目录不会自动获得第二个活动节点身份；备份必须显式恢复后才能参与网络。

`contains` 表示默认聚合范围中的父子关系，允许多父、禁止成环。`related` 表示横向联系，不自动扩大子树范围。菱形图中同一来源事实只计一次；不同项目对同一需求的贡献仍是不同事实，只有明确业务映射才能做需求级汇总。

第一版使用一个网络内的单一关系权威和版本号。对关系的修改通过同一受控命令执行版本比较、引用检查和拓扑校验，不允许同时编辑数据库与 YAML。多个网络权威之间的联邦、跨库原子修改和跨机器强一致性属于独立能力，不由单库事务自动获得。

局部 SQL 更新减少了文件重写，但当前原型仍使用全局关系版本和完整拓扑校验。无关修改可能使旧版本写入冲突，查询期间的关系变化也需要显式处理；数据库本身没有消除这些成本。第一版保留这一容易核验的约束。只有真实修改冲突率、校验时长或查询失效率超过事先制定的目标时，才追加分区修订和局部校验实验，不能预先宣称任意规模修改都互不影响。

“上级可读”表示可以在授权资料范围内按需读取全部工作信息，默认范围是已登记工作流资料。它不等于整个磁盘、凭据或源码都自动开放。登记时明确授予下级资料的读能力；跨节点写入另立能力，第一版汇总不提供该能力。横向联系需要单独读授权。

关系存在、读取授权和资料可达是三个不同事实。请求固定授权成员集合，执行时检查授权；拒绝、撤回、不可达、格式不支持和预算未覆盖必须单独记录，不能改写为“没有工作”。本次原生 Agent 的轨迹核查不等于多租户操作系统隔离；正式运行适配器应只暴露受限读取工具。

## 4. 按需执行与上下文控制

一次运行包含 `run_id`、模板版本、入口、范围、节点视图、时间区间、关系/授权版本、预算和取消状态。模板定义需要收集的业务字段及证据要求，由程序确定目标集合和分批，节点读取任务使用相同模板。

实验包装层现已提供 `query` 入口作为模型调用前的有界门面：`self/subtree`、`max_nodes`、`max_depth`、`timeout_seconds` 和 `max_bytes` 均有默认上限，超限返回 `partial`、`failed` 或明确的 `skipped`。当前 `max_bytes` 约束响应 JSON；实际模型 token 仍须由运行器观测和单独限制。入口在独立工作者进程中执行，超时后回收工作者；它不是跨平台沙箱或恶意调用者隔离。日期范围暂保留在底层事实查询契约，工作项摘要没有可靠业务活动日期时不做日期推断。

流程如下：

1. 程序读取关系权威，固定本次应覆盖节点集合；模型只看到必要目录页。
2. 根据来源数量与字节预算准备只读任务；每个模型调用使用独立上下文。
3. 工作者返回结构化事实、来源引用、覆盖与缺口，不重写其他节点资料。
4. 程序检查身份、类型、来源可核验性、重复、冲突与覆盖集合，保存运行产物。
5. 汇总 Agent 阅读有界汇总数据并撰写报告；需要细节时按页下钻。

组织层级不强制等于执行层级。不能让每个祖先都反复传递所有后代事实，也不能将自然语言摘要作为唯一向上传递的证据。具体小任务与大任务调度策略以选型报告为准。

预算分别限制节点数、深度、来源文件大小与数量、并发、总时长、单次输入、单次输出、累计模型 token 和工具调用次数。JSON 字节预算不冒充 token 预算。连续翻页到同一会话仍会累计上下文，所以大任务必须拆到 fresh 工作者，最终报告只消费受控结果。正式读取器需支持分段读取和超大来源的明确缺口，不能先把无限大的原文读入内存后才检查模型预算。

响应分为 `full`、`partial` 和 `failed`。`full` 只表示已登记且获授权的固定范围内完成了指定模板的读取，不表示未登记项目、未记录活动或所有业务真相均已覆盖。超过预算、冲突、来源变化或缺口时必须显式降级。

对 N 个节点的完整汇总仍有相应的总工作量。本产品只控制单次上下文和总预算，不承诺无限节点、任意深度下成本恒定。

## 5. 一致性、恢复与退出

关系修改使用版本比较和事务/锁，避免两笔看似合法的并发修改构成环。提交结果不确定时先重读并对账，不盲目重试。操作 ID 与修订号承担幂等和恢复责任。

关系快照与节点事实快照分开描述。不同节点可以在不同时间被观察；文件读取前后校验能发现受测变化，但不能提供全网同一瞬间的事务快照。需要强快照的未来场景应采用不可变来源视图或明确的版本固定协议。

节点加入、退出和迁址会涉及本地身份与关系库两个位置，不能宣称单库事务已覆盖二者。产品需提供操作记录、可重复对账及明确的中间状态；本地工作在此期间仍可进行。退出只断开网络联系，不删除项目工作资料。

备份分别覆盖关系权威、项目资料和必要运行记录。SQLite 使用备份 API，服务库按版本和版别选择原生备份。逻辑导出用于校验、迁移和恢复演练，不替代所有原生灾备能力。迁移采用停止关系写入、导出、导入新权威、核验、切换单一指针；保留旧权威备份，禁止双写。

## 6. 正式开发顺序与退出条件

| 阶段 | 交付 | 必须满足的退出条件 |
| --- | --- | --- |
| D1 本地核心与可选网络分离 | 网络命令入口、版本化身份与关系库、加入/退出/迁址 | 原稳定回归全过；根/中间/叶子独立使用一致；网络配置或服务故障不阻止本地操作 |
| D2 确定性查询与证据 | 授权范围、关系快照、来源 inventory、run/page/evidence、备份恢复 | 多父去重、冲突、撤回、超时、超预算和来源变化有明确状态；原文不被聚合修改 |
| D3 真实 Agent 运行适配 | fresh 工作者、模板、模型用量/取消/重试、程序验收、最终报告 | 将模型输出作为不可信输入；业务场景盲测覆盖进展与完成、跨周、未知时间和提示诱导；不依赖固定题目 oracle 做线上校验 |
| D4 小范围实际使用 | 隔离安装方式、真实项目只读试用、升级/回退、使用说明 | 用户代表性周报与本地开发均验收；异常恢复演练；达到事先确定的产品 SLO，再决定合并发布 |

先完成本地个人使用版本。只有实际跨机器协作需求出现时才产品化服务后端，避免一开始承担多后端长期维护成本。阶段内可复用实验代码和测试，但需要评审接口、默认行为、依赖加载、安全边界和迁移策略，不能直接把实验目录复制进安装版。

本阶段的选型完成不自动触发主分支合并、安装同步或真实项目改造。
