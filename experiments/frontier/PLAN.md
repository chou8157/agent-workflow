# 多节点工作流：多方案验证与选型计划

版本：v1，2026-10-10。性质：实验评估协议，不是最终产品架构。

## 1. 产品目标与授权

- 用户目标：在任意节点独立处理本项目，或主动选择聚合其下级；两者自由切换。
- 节点可以同时拥有自身工作和下级，不限定为互斥的项目/聚合类型。
- 正常单项目工作只更新自身记录。汇总按需发起，不要求后台向上同步。
- 父级可读取已纳入授权范围的下级工作资料；读权限与跨节点写权限分开。
- 用户已授权实验分支、worktree、子 Agent、方案规划和初步实现/测试。
- 工作仅在当前实验 worktree；main、已安装 skill 和真实业务项目不作为写入目标。
- 存储和调度都未定型；实验结果允许为“证据不足，暂不选型”。

## 2. 固定需求与可变设计

固定：自治、可选聚合、来源可追溯、事实唯一、明确缺失/冲突、受控资源、退出可恢复。

待验证：关系如何持久化、集中/分区部署、索引策略、调度拓扑、真实 Agent 运行适配器。
不先定义一套长期插件 API；先固定外部行为和测试输入输出，再用最小可替换实验接口比较。
原生优化可以参加，但必须记录额外开发量及配置；缺失实现不能冒充候选产品的固有限制。

## 3. 候选登记（不按偏好排序）

| ID | 具体实现候选 | 关系权威与恢复责任 | 首轮范围 |
|---|---|---|---|
| F | 本地文件 + 程序查询 + 写锁 + 原子替换 | 文件是关系权威，需备份；内存索引可重建 | 可运行参考实现；不把 JSON 直接塞给 Agent |
| S | 本地 SQLite | 数据库是关系权威，需事务/备份/迁移；项目文档仍在本地 | 同机单用户、多进程查询/写入 |
| P | PostgreSQL | 服务端关系库是权威，需备份/迁移/权限 | 专用隔离实例，验证多客户端场景 |
| G | 图数据库（先以 Neo4j 为具体研究实例） | 图库是权威，需约束/备份/迁移 | 专用隔离实例，验证多跳关系与更新 |

F 的单快照文件是一个具体实现，不代表所有文档方案；若其写放大明显，追加分片/日志变体并单列成本。
服务候选的运行环境缺失记为 not_run/environment，不记为功能失败，也不据此宣布本地方案胜出。
同一关系不同时在数据库和 YAML 中独立编辑。导入/导出必须声明方向和版本，不能双向静默合并。
只在有完整权威数据可恢复时称为“可重建索引”；不能将权威关系库当作可随意丢弃的缓存。

## 4. 调度候选（与存储分开比较）

- C：中央执行器按分页/批次读取节点，由程序执行合并。
- H：按层委派，子执行器返回事实引用及覆盖信息，再由程序合并。
- M：混合执行，按子树/任务量划分批次；在 C/H 得到结果后验证。
- 节点组织层级不强制等于执行拓扑。逐层自然语言摘要不作为唯一事实传递形式。
- 初轮确定性执行器仅验证图遍历、去重、查询边界和传输量，不称为真实 Agent 编排成功。

## 5. 一票否决的验收条件

| ID | 不变量 | 验证方法 |
|---|---|---|
| A1 | 网络能力未启用/不可用时单节点仍正常 | 在同一项目副本上执行本地流程；网络组件缺失/损坏再执行，对比语义和文件 |
| A2 | 聚合只读，普通工作不向外同步 | 对全部节点源文件前后计算哈希；写入仅允许实验控制目录 |
| A3 | 相同范围在平铺、深层、多父结构下事实等价 | 独立集合 oracle；比较事实 ID、值和来源，不比较摘要措辞 |
| A4 | 完整性有据可查 | 固定成员/关系版本、请求范围、时间区间；目标节点都有成功/拒绝/失败/未覆盖状态 |
| A5 | 不静默重复或消解冲突 | 同事实经多路径只计一次；同身份不同值必须报冲突，不用版本号伪装成两件事 |
| A6 | 关系修改具有一致性 | 并发创建成环、重复边、失效引用、版本冲突、进程中断测试 |
| A7 | 来源、时间和权限语义明确 | 来源失效、跨周时区边界、读取期间修改、权限撤回、路径逃逸测试 |
| A8 | 预算超限可见 | 节点/深度/时间/输出预算超限产生 partial/失败，不当作完整空结果 |

任一硬门槛失败只说明该实现暂不合格；修复后保留旧证据并重新运行。未运行等于待验证。
“完整”只相对于本次已固定且可枚举的授权成员范围，不能宣称覆盖未登记项目或所有历史工作。
源头没有记录的工作不能被可靠恢复；要报告记录覆盖限制，不靠模型补造。

## 6. 数据与场景矩阵

- 固定合成数据种子 20261010；样本与预期值独立生成并记录哈希。
- 节点数 1/10/100/1000；平铺、均衡树、深链、多父 DAG；非法环另作负例。
- 每节点事实数 0/10/100，先跑小矩阵；增加压力档时公开运行参数，不一次做笛卡尔积。
- P1 首轮规模矩阵每节点 1 条命中事实，另有 2 条时间窗外事实；随后补 10/100 条事实的小矩阵。零事实由契约测试覆盖。
- 每一级均含“自身事实”；同名任务、同一需求的多项目贡献、共享事实必须分开建样本。
- 查询使用半开区间 [start, end)，显式时区；活动时间、完成时间、采集时间分别建字段。
- 关系读写与内容提取分开测试：先只比关系操作，再复用相同事实读取器测试端到端。
- 文件路径变化保持逻辑身份；分支/worktree 作为不同数据视图，不能默认合并为同一快照。
- 故障：断开节点、损坏数据、拒绝访问、超时、重试、重复响应、取消、进程崩溃、旧协议。
- 并发：1/4/16 个请求或写者；读多写少与集中关系修改分开。

## 7. 测量与公平性

- 基线：固定源码提交、Python/数据库版本、机器信息；先跑现有测试再开始候选实现。
- 相同数据、问题、返回字段、持久性要求；不能让某方案用内存而另一方案计入持久化。
- 短基准每格至少 5 次、轮换候选次序；输出全部样本、median、min/max。5 次不宣称可靠 p95。
- 失败/错误保留在总分母及原始样本中，耗时汇总只统计通过样本；不能用提前失败时间参与性能排名。
- 初始化、首次查询、重复查询、写入、持久化重开、恢复分别计时；不将 OS 页缓存冒称彻底冷缓存。
- 记录响应字节数、最大单页、节点调用数、总工作量、结果规模、资源和部署步骤。
- 字节数不能冒充模型 token；程序分页也不能证明聊天上下文自动清空。
- 真实 Agent 阶段固定模型/提示/预算，记录根与子调用 token、耗时、失败和证据准确率，重复测试。
- 全量正确处理 N 个节点仍需相应工作量；只限制单调用/单上下文负载，不承诺总成本恒定。
- 性能数据先探索、后定产品 SLO；不能看到赢家后补阈值包装为事先标准。

## 8. 分阶段执行与停止规则

| 阶段 | 交付/退出条件 | 当前安排 |
|---|---|---|
| P0 | 需求、候选、硬门槛、资料、源码基线、独立评审 | 本轮先完成；写入证据指针 |
| P1 | F/S 可运行关系原型 + C/H 确定性执行 + 独立 oracle + 初步规模数据 | P0 审阅后启动，不改稳定产品 |
| P2 | P/G 隔离实例实测，同等行为；并发/中断/恢复与优化变体 | 环境未具备就记录缺口，保留候选 |
| P3 | 真实 Agent 读取统一项目副本，比较 C/H/M，验证上下文/语义/权限 | 不用 P1 模拟数据替代；运行适配器先核实 |
| P4 | 真实记录副本试用、迁移/退出、持久化恢复、选型复核 | 所有必要硬门槛有证据再决策 |

发现跨边界写入、事实污染、错误完整性声明时暂停该候选，保留失败输入。
每阶段允许继续、修复后复测、搁置或退出，不因为总投入增加而强行选出赢家。
不把一次会话结束等同整个实验完成；阶段状态和下一步必须可在新会话恢复。

## 9. 决策方式

先硬门槛，后比较通过者的准确性、延迟/成本、运维、迁移和可理解性；未实测者单列。
本地个人与多机器团队为两个场景，不能用任一场景权重预先淘汰另一类方案。
先展示原始指标与 Pareto 权衡，不给主观总分制造精确性；若需要加权，事先确认权重并做敏感性分析。
允许按部署场景提供两种后端，但必须评估双后端维护成本；不承诺 SQLite 到 PostgreSQL 无缝迁移。
最终选择必须写清已验证规模、已知失败、未验证范围、恢复方法和再次评估触发条件。

## 10. 协作与记录

- 主 Agent：实验计划、接口、调度、证据整合、验收判断和工作项收口。
- 调研 Agent：仅 research.md；基线 Agent：仅 baseline.md/evidence/baseline.json。
- 独立审阅 Agent：仅 evaluation-review.md；后续实现按文件所有权拆分。
- 复用已有实验 worktree；无文件交叉的任务无需额外 Git 分支。出现冲突再拆 worktree。
- 子 Agent 只回传结论与文件指针；原始批量输出写 evidence，主上下文不加载全量数据。
- 工作项 current-status 是恢复入口；PLAN 是评估规则；RESULTS 是结果解释；原始 JSON 是证据。
- main/安装版、提交/推送/合并/发布不由实验成功自动触发。
