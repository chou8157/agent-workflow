# 运行模型

## 核心定位

本 skill 是一个“智能体工作流生成与迭代总 skill”。它不把项目一次性解释完整，而是为项目建立可持续更新的工作流目录，让智能体在接手、开发、记录、改进时按稳定框架行动。

## 产物边界

- 单项目核心产物：项目根 `AGENTS.md` + `.agent-workflow/`。
- 多项目核心产物：独立 `.agent-workflow-shared/`，或用户指定的共享目录名。
- `AGENTS.md` 是入口和强约束，不承载详细项目百科。
- `.agent-workflow/` 是主体，承载流程、项目理解、模块索引、门禁和记录。
- `30-records/work-items/` 是工作项上下文层。项目公共信息仍在原目录；工作项只保存本需求、任务或缺陷的私有事实。

## 内部模式

- `init`：初始化单项目工作流。
- `init shared`：初始化多项目共享工作流。
- `use`：日常开发前渐进读取工作流。
- `record`：开发后沉淀进展、状态、验证、风险和模块索引。
- `improve`：优化当前项目工作流；全局 skill 规则变更需确认。
- `check`：手动自检工作流结构和一致性。
- `migrate`：从旧工作流目录迁移到新结构。
- `upgrade`：把已生成工作流安全升级到当前结构版本。

## 自然语言路由

- “接手项目 / 初始化工作流 / 新项目” → `init`
- “按工作流做 / 开始开发 / 看当前状态” → `use`
- “记录一下 / 归档 / 沉淀这次开发” → `record`
- “以后都这样 / 优化规则 / 改工作流” → `improve`
- “多项目 / 上下游 / 共享链路” → `init shared`
- “检查工作流 / 自检 / 看结构是否完整” → `check`
- “迁移旧 agent_docs / 整理旧工作流” → `migrate`

## 默认安全边界

- 默认只读当前目标项目；外部资料必须由用户提供或由项目显式引用。
- 默认可以写入 `.agent-workflow/`；大幅改写已有 `AGENTS.md` 前必须先给计划或 diff。
- 不确定事实进入 `10-project/unknowns.md`，不能写成确认规则。
- 真实验证才写入 `30-records/validation-log.md`。
- Git 与 worktree 不属于默认依赖。启用后只记录和核验代码状态；创建、切换、删除 worktree 必须由用户明确触发并按高风险流程处理。
