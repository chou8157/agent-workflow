# 工作流收口模式（finalize）

## 触发条件

当本轮实际执行了代码/配置/文档开发、测试或人工验收、工作项状态变更，或生成了交付物时，任务结束前默认执行一次收口。纯讨论、阅读、方案规划、未产生项目文件或验证事实的任务不触发。

## 收口边界

- 只选择一个明确的目标工作项；多个进行中工作项时必须先确认，不能猜测。
- 自动写入的内容必须来自本轮真实命令、文件变更、测试输出或用户明确结论。
- 默认更新目标工作项的 `current-status.md`、新增一条 `progress/` 记录，并将真实测试写入 `validation-log.md`。
- 工作项完成、阻塞或归档时，先通过 `task_context.py set-status` 更新 `.state.json`。
- 项目级 `30-records/current-status.md`、决策、风险和模块索引仅在本轮确实产生跨任务事实时更新；不能为了收口复制工作项摘要。
- Memory 只接收已确认、稳定且可复用的事实；普通收口不得自动写入。
- 外部周报、阶段报告和交付物仍必须走 `delivery` 的草稿、检查、批准和发布流程，收口不得自动发布。

## 事实收集顺序

1. 读取目标工作项和当前状态。
2. 收集本轮实际变更文件、执行过的测试/命令及其结果。
3. 记录未执行的验证和残余风险，不得推断为通过。
4. 根据明确结果更新工作项状态；无法判断完成度时保持原状态并列出待确认项。
5. 生成一条简短、幂等的进展记录，避免同一事实重复写入。
6. 运行工作流检查，检查失败时在收口中报告，不伪造完成结论。

## 不自动做的事情

- 不从自然语言推断项目整体完成、风险消失或决策生效。
- 不覆盖用户已有文档，不删除或归档历史记录。
- 不把调试输出、中间草稿或未确认判断写入长期 Memory。
- 不因为工作项完成自动修改项目级生命周期状态。

## 最终报告要求

向用户说明：实际变更、真实验证、当前工作项状态、未验证项和残余风险。若未触发收口，应明确说明“本轮未产生项目事实，未更新工作流文档”。
