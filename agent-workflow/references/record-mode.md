# 记录模式（record）

## 目标

在用户明确要求记录、归档、沉淀时，把本次工作转化为可恢复上下文。

## 项目级与工作项级记录

- 项目级 `30-records/` 只记录跨任务的里程碑、决策、风险、验证和待修复项。
- 实际开发需求默认记录到目标工作项目录。工作项必须更新 `current-status.md`，详细进展进入新的 `progress/NNN-阶段标题.md`。
- 用户触发“切换任务”时，可以先为离开的工作项记录真实检查点，再恢复目标工作项。

## 项目级必须更新

- 只有本次工作影响项目整体时，才更新 `30-records/progress-log.md` 和 `30-records/current-status.md`。

## 按事实触发

- 执行过测试、命令或人工验收：更新目标范围内的 `validation-log.md`。
- 发现风险：更新目标范围内的 `risk-log.md`。
- 发现已确认 Bug 或债务：更新目标范围内的 `pending-fixes.md`。
- 形成稳定决策：更新目标范围内的 `decision-log.md`；重大、难逆且有权衡的决策才建 ADR。
- 深度阅读模块：更新或创建 `15-modules/*.md`。

## 记录原则

- 只记录真实发生的事情。
- 未验证时写“未验证原因”和“建议验证动作”，不能写通过。
- 工作项 `current-status.md` 只保留当前摘要，详细历史按阶段进入 `progress/`；不能把多个阶段堆进一个无限增长的文件。
- 模块索引只记录位置、职责、入口和注意事项，不复制详细逻辑。

## 记录检查清单

执行 `record` 时按顺序判断，不需要每项都写：

1. **本次目标**：这次任务要解决什么，最终完成到什么程度。
2. **实际变更**：改了哪些文件、文档、配置或流程。
3. **阅读范围**：深度阅读了哪些模块；如有价值，更新 `15-modules/`。
4. **验证事实**：真实执行了哪些测试、命令或人工验收；没有执行就写未验证原因。
5. **风险和问题**：风险进 `risk-log.md`，已确认问题进 `pending-fixes.md`。
6. **决策**：轻量决策进 `decision-log.md`；重大决策才建 ADR。
7. **当前状态**：更新目标工作项的 `current-status.md`；只有项目整体状态变化时才更新根 `current-status.md`。
