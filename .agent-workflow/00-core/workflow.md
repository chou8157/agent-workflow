# 工作流程

## 标准流程

1. 接需求：明确目标、范围、风险等级和是否需要确认。
2. 只读分析：先阅读入口文档和相关代码，不急于修改。
3. 方案细化：说明影响面、修改点、验证方式和风险。
4. 执行修改：小步变更，只改相关内容。
5. 验证：运行可行的测试、命令或人工检查。
6. 收口：说明改了什么、如何验证、残留风险。
7. 记录：仅在用户要求或任务有沉淀价值时更新记录。

## 任务分级

- 低风险：文档、小范围无副作用修改；默认可直接执行。
- 中风险：业务逻辑、接口、数据读写、测试策略；必须先分析和给方案。
- 高风险：真实环境、副作用操作、权限、安全、发布、数据迁移；必须确认方案、验证和回滚/止损。
